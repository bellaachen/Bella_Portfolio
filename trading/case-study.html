THE PRODUCT CHALLENGE

Keep the order connected to the chart.

A pending order is defined by its price relative to the market. The workflow brings order placement onto the chart so users can choose a level, see the order type, and adjust entry, take-profit, or stop-loss prices in context. The key product goal is to keep the user in control: changes remain a draft or preview until confirmed.

INTERACTION RULES

Make order behavior legible before it is sent.

Order type follows side + price

Buy below Ask = Buy Limit; buy above Ask = Buy Stop. Sell below Bid = Sell Stop; sell above Bid = Sell Limit. The type updates as the draft price moves.

Entry and protection levels have separate handles

Drag the order line to move entry. Drag TP or SL chips to set protection levels. The prototype previews their estimated P&L and keeps the offsets when entry moves.

Edit existing orders with a preview

Dragging a pending order creates a preview state with Confirm and Cancel. Open-position entry stays fixed; TP and SL can be adjusted separately.

Market data is simulated

The demo simulates price movement, order fills, and terminal updates. It does not connect to a live account or route real orders.

REFLECTION

A chart is both an analysis surface and an order surface.

The interaction is useful only when the meaning of each line remains clear. Showing the order type, price, and pending or confirmed state together helps users understand what will happen before they submit. Further validation should cover price precision, minimum distance rules, market-crossing behavior, and touch input.
